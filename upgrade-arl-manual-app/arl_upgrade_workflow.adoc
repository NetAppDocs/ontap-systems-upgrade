= ARL upgrade workflow
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ../media/

[.lead]
Before you upgrade the nodes using ARL, you must understand how the procedure works. In this document, the procedure is broken down into several stages.

== Upgrade the node pair

To upgrade the node pair, you prepare the original nodes and follow the upgrade steps on both the original and new nodes. Then, you decommission the original nodes.

== ARL upgrade sequence overview

You upgrade the original controller hardware with the replacement controller hardware, one controller at a time, taking advantage of the HA pair configuration to relocate the ownership of non-root aggregates. You must relocate all non-root aggregates twice to reach the correct upgraded node.

Each aggregate has a home owner and current owner. The home owner is the actual owner of the aggregate, and the current owner is the temporary owner.

The following illustration shows the stages of the procedure. The thick, light gray arrows represent the relocation of aggregates and the movement of LIFs, and the thinner black arrows represent the removal of the original nodes. The smaller controller images represent the original nodes, and the larger controller images represent the new nodes.

image:arl_upgrade_manual_image1.PNG[Illustration showing the stages of the ARL procedure]

Learn about the high-level tasks you perform during each stage and the state of aggregate ownership at the end of the stage. Detailed steps are provided later in the procedure.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png[One]link:determine_aggregates_on_internal_drives.html[Stage 1: Prepare for upgrade]
[role="quick-margin-para"]
During Stage 1, if required, you confirm that internal disk drives do not contain root aggregates or data aggregates, prepare the nodes for the upgrade, and run a series of prechecks. If required, you rekey disks for Storage Encryption and prepare to netboot the new controllers.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png[Two]link:relocate_non_root_aggr_node1_node2.html[Stage 2: Retire node1]
[role="quick-margin-para"]
During Stage 2, you relocate non-root aggregates from node1 to node2 and move non-SAN data LIFs owned by node1 to node2, including failed or vetoed aggregates. You also record the necessary node1 information for use later in the procedure and retire node1.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png[Three]link:install_boot_node3.html[Stage 3: Install and boot node3]
[role="quick-margin-para"]
During Stage 3, you install and boot node3 and map the cluster and node-management ports from node1 to node3. If you are using NetApp Volume Encryption (NVE), you restore key-manager configuration. Then, you move data LIFs and SAN LIFs belonging to node1 from node2 to node3, relocate all aggregates from node2 to node3, and move the data LIFs and SAN LIFs owned by node2 to node3.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png[Four]link:record_node2_information.html[Stage 4: Retire node2]
[role="quick-margin-para"]
During Stage 4, you record the necessary node2 information for use later in the procedure and then retire node2.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png[Five]link:install_boot_node4.html[Stage 5: Install and boot node4]
[role="quick-margin-para"]
During Stage 5, you install and boot node4 and map the cluster and node-management ports from node2 to node4. If you are using NetApp Volume Encryption (NVE), you restore key-manager configuration. Then, you move data LIFs and SAN LIFs belonging to node2 from node3 to node4, relocate node2 aggregates from node3 to node4, and move the data LIFs and SAN LIFs owned by node2 to node3.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png[Six]link:manage_authentication_kmip.html[Stage 6: Complete the upgrade]
[role="quick-margin-para"]
During Stage 6, you confirm that the new nodes are set up correctly and set up Storage Encryption or NetApp Volume Encryption if the new nodes are encryption-enabled. You should also decommission the old nodes and resume SnapMirror operations.
